Non-Functional Requirements Specification (Non-Functionality)

St. Cecilia's College - Cebu, Inc. • AlumNet System Documentation

NFR - # Category Non-Functional Requirements
The system shall load initial dashboard views, alumni directory pages, and administrative consoles within two (2.0) seconds over standard broadband (≥ 5 Mbps) or 4G LTE mobile data connections.
The system shall execute Cloud Firestore search, indexing, and filtering queries within eight hundred (800) milliseconds by leveraging optimized composite indexes across all multi-attribute collections.
The system shall automatically compress user-uploaded avatars, banner images, and gallery photographs into modern web formats (JPEG/WebP) to maintain image asset sizes below 500 KB and reduce network bandwidth consumption.
The system shall authenticate and authorize all transactions using Firebase Authentication cryptographic JSON Web Tokens (JWT) with automated token refreshing and secure cookie-based session management.
The system shall strictly enforce role-based access control policies at both the client-side router navigation layer and the server-side Cloud Firestore Security Rules layer, preventing unauthorized document reads, modifications, or privilege escalation.
The system shall mandate Transport Layer Security (TLS 1.3 / HTTPS) for all data in transit across client browsers and Firebase cloud servers, and enforce 256-bit Advanced Encryption Standard (AES-256) for all data stored at rest.
The system shall strictly comply with the Philippine Data Privacy Act of 2012 (Republic Act No. 10173) by isolating sensitive student registrar records, encrypting user authentication credentials in a dedicated vault (), and providing granular user visibility controls.
The system shall maintain an operational service availability of at least 99.5% uptime during regular academic semesters, utilizing Google Cloud Platform’s multi-zone fault-tolerant infrastructure.
The system shall gracefully handle intermittent mobile network dropouts or backend latency, implementing client-side offline data caching and displaying non-intrusive retry prompts without application crashing or loss of unsaved form data.
The system shall support at least five hundred (500) concurrent active sessions and sustain temporary spikes of up to two thousand (2,000) requests per minute during peak college events (such as commencement ticketing and homecoming registration) without degradation of service.
The system shall utilize Google Cloud Firestore’s serverless auto-scaling architecture to seamlessly absorb continuous expansion in alumni cohort records, job applications, and messaging channels without requiring manual database re-provisioning.
The system shall present an institutional, visually balanced user interface adhering to St. Cecilia's College official branding (crimson and warm neutral palette), ensuring new users can complete account activation and primary tasks within ten (10) minutes without external training.
The system shall dynamically adapt its user interface across all target viewports, including widescreen desktops (1920x1080), standard laptops (1366x768), tablets (768x1024), and mobile smartphones (375x667 and above), maintaining minimum touch target sizes of 44 by 44 pixels.
The system shall conform to Web Content Accessibility Guidelines (WCAG 2.1 Level AA), providing minimum optical contrast ratios of 4.5:1 for standard text, semantic HTML element tagging, and keyboard-navigable interactive controls.
The system codebase shall be engineered using a modular React and TypeScript architecture with clean separation of presentation components, business logic hooks, and centralized Firestore service adapters to enable straightforward future extension.
The system shall maintain comprehensive type safety across all interfaces and data models, passing linting rules with zero breaking errors and featuring automated test suites verifying critical authentication, verification, and registration workflows.
The system shall operate with full functional parity and visual fidelity across all major modern web browsers, including Google Chrome (version 100+), Mozilla Firefox (version 100+), Apple Safari (version 15+), and Microsoft Edge (version 100+).
The system shall comply with Progressive Web App standards and Capacitor runtime specifications, enabling service-worker static asset caching, homescreen installability, and seamless packaging for Android and iOS mobile deployment.
The system shall immutably record all privileged administrative interventions, user role changes, account status suspensions, and registrar masterlist modifications in the collection, capturing precise ISO 8601 timestamps, actor UIDs, action types, and client IP addresses.
The system shall validate all inbound data payloads against strict schema constraints before persistence, preventing duplicate registrations through unique index enforcement on student IDs and emails, and maintaining logical referential integrity across all 19 entities.
