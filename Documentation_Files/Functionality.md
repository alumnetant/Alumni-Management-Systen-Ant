# Functional Requirements Specification (Functionality)
**Project Title:** AlumNet: A Web and Mobile-Based Alumni Networking System  
**Institution:** St. Cecilia's College - Cebu, Inc.  
**System Architecture:** Firebase Cloud Firestore & React / TypeScript Web Application  

---

## Functional Requirements Table

| FR - # | User Role | Functional Requirements |
| :---: | :--- | :--- |
| **FR-01** | **Alumni** | **Alumni Online Registration & Identity Claiming:** The system shall allow graduating students and alumni to register using their official Institutional Student ID Number (e.g., `SCC-YYYY-NNNNN`), automatically cross-matching the input against the institutional Registrar Graduate Masterlist (`registry_records`) to verify graduation status and claim their official alumni account. |
| **FR-02** | **Alumni** | **Account Authentication and Credentials Management:** The system shall allow the Alumni to securely authenticate using their registered institutional or personal email address and password, maintain secure login sessions, reset forgotten credentials via email verification links, and access self-service account recovery. |
| **FR-03** | **Alumni** | **Alumni Profile Setup and Personalization:** The system shall enable the Alumni to create, edit, and maintain their comprehensive personal profile, including full name, graduation batch year, academic degree program, current job title, employing company, residential location, biographical summary, contact telephone number, profile picture, and cover banner photo. |
| **FR-04** | **Alumni** | **Professional Experience and Skills Portfolio:** The system shall allow the Alumni to record and showcase their employment history, collegiate educational background, technical proficiencies, professional certifications, and industry skills on their public alumni profile. |
| **FR-05** | **Alumni** | **Profile Privacy and Visibility Configuration:** The system shall enable the Alumni to configure personal privacy settings, selectively controlling whether their contact telephone number, email address, and employment details are publicly visible, restricted strictly to verified alumni connections, or hidden. |
| **FR-06** | **Alumni** | **Alumni Directory Search and Advanced Filtering:** The system shall provide the Alumni with an interactive directory to search and discover former classmates and fellow graduates using multi-parameter filters, including full name, graduation batch year, academic course, employing organization, industry sector, and geographic region. |
| **FR-07** | **Alumni** | **Connection Requests and Professional Networking:** The system shall allow the Alumni to send connection invitations to fellow alumni, accept or decline incoming requests, view connection statuses (`pending`, `accepted`, `declined`), and manage their mutual professional network (`connections`). |
| **FR-08** | **Alumni** | **Direct Peer-to-Peer 1-on-1 Messaging:** The system shall allow the Alumni to initiate and participate in private, real-time 1-on-1 direct conversations (`conversations`) and instant messaging (`conversation_messages`) with connected alumni peers, featuring message timestamps and unread message indicators. |
| **FR-09** | **Alumni** | **Cohort and Group Discussion Lounges:** The system shall allow the Alumni to join and actively participate in group chat rooms (`chats`) organized by academic department, graduation batch, or registered college event cohorts, featuring multi-user discussions and media sharing. |
| **FR-10** | **Alumni** | **Community Feed Publishing and Milestone Sharing:** The system shall enable the Alumni to publish career milestones (promotions, new certifications, awards), professional updates, and campus memories to the Community Feed (`feed_posts`), as well as like, react to, and comment on updates shared by fellow Cecilians. |
| **FR-11** | **Alumni** | **Institutional Announcements & Advisories Feed:** The system shall provide the Alumni with an announcement board displaying official institutional bulletins, academic updates, career opportunities, and emergency advisories published by the college administration. |
| **FR-12** | **Alumni** | **College Event Browsing and RSVP Seat Reservation:** The system shall allow the Alumni to browse upcoming college reunions, homecoming gatherings, career webinars, and workshops (`events`), reserve seats for themselves and allowable guests, and monitor their reservation confirmation status (`event_reservations`). |
| **FR-13** | **Alumni** | **Digital Event Ticket and QR Code Generation:** The system shall automatically generate a digital entry ticket with a cryptographically secure, scan-verifiable QR code payload upon successful event reservation, enabling contact-free check-in at event venues. |
| **FR-14** | **Alumni** | **Job Opportunities Search and Filtering:** The system shall allow the Alumni to browse verified job openings, internships, and career opportunities (`opportunities`) submitted by partner companies, filtering by job type (full-time, part-time, internship), required course, salary range, and company name. |
| **FR-15** | **Alumni** | **Direct Job Application and Resume Submission:** The system shall enable the Alumni to apply directly for posted career vacancies by uploading their professional resume (PDF format), drafting a personalized cover letter, submitting their profile credentials, and reviewing algorithmic job-matching scores. |
| **FR-16** | **Alumni** | **Job Application Tracking and Status Updates:** The system shall allow the Alumni to monitor the real-time review progress of their submitted job applications across hiring pipeline stages (Pending, Reviewed, Shortlisted, Interview, or Hired). |
| **FR-17** | **Alumni** | **Campus Photo Gallery & Memory Archives:** The system shall allow the Alumni to view high-resolution photographic archives (`gallery`) documenting historical commencement ceremonies, alumni homecomings, and campus heritage. |
| **FR-18** | **Alumni** | **Real-Time In-App and Push Notifications:** The system shall deliver real-time notifications (`notifications`) to the Alumni regarding incoming connection requests, direct messages, event registration updates, job application status changes, and urgent administrative announcements. |
| **FR-19** | **Alumni** | **Two-Factor Authentication (2FA) and Security Vault:** The system shall allow the Alumni to enable time-based one-time password (TOTP) two-factor authentication, generate single-use emergency backup recovery codes, and review their recent login activity. |
| **FR-20** | **Employer** | **Corporate Employer Registration & Vetting:** The system shall allow corporate employers, industry partners, and recruiting representatives to register an Employer account by providing company trading name, business website, industry classification, recruitment email, and proof of legitimate business operation. |
| **FR-21** | **Employer** | **Company Profile Branding and Recruitment Hub:** The system shall enable the Employer to manage their corporate profile, upload high-resolution company logos, describe corporate culture and employee benefits, and publish verified contact channels for Cecilian applicants. |
| **FR-22** | **Employer** | **Job Vacancy Creation and Publishing:** The system shall allow verified Employers to author and publish job openings (`opportunities`), specifying position title, employment classification (full-time, part-time, internship), job location/remote arrangement, compensation range, required degree program, and candidate qualifications. |
| **FR-23** | **Employer** | **Job Listing Lifecycle Management:** The system shall allow the Employer to edit job descriptions, update skill requirements, pause incoming submissions, close filled positions, and archive expired opportunities. |
| **FR-24** | **Employer** | **Applicant Tracking Dashboard (ATS):** The system shall provide the Employer with a dedicated recruitment dashboard to review all candidate applications (`job_applications`) received for their published vacancies, organized by position title and submission timestamp. |
| **FR-25** | **Employer** | **Candidate Resume Screening and Inspection:** The system shall allow the Employer to inspect applicant profile credentials, preview submitted PDF resumes directly in the browser, review candidate cover letters, and examine algorithmic candidate-to-job matching scores. |
| **FR-26** | **Employer** | **Hiring Pipeline Workflow Management:** The system shall enable the Employer to update the progress status of candidate applications (Pending, Reviewed, Shortlisted, Interview Scheduled, Offer Extended, Hired, or Rejected) and record internal recruitment evaluation notes. |
| **FR-27** | **Employer** | **Candidate Direct Communication:** The system shall allow the Employer to contact applicants directly via secure email or platform communication channels to arrange interview schedules and convey formal employment offers. |
| **FR-28** | **Employer** | **Recruitment Alerts and Notification Center:** The system shall notify the Employer in real time whenever an alumnus submits a new application to their active listings or when college administrators update their company verification status. |
| **FR-29** | **Moderator** | **Alumni Verification Queue Triage:** The system shall provide the Moderator with a verification triage queue displaying newly registered alumni accounts, allowing them to cross-reference submitted credentials against institutional registrar records and approve, flag, or reject registration requests. |
| **FR-30** | **Moderator** | **Verification Discrepancy Flagging:** The system shall enable the Moderator to flag questionable or mismatched alumni registration attempts, request supplementary proof of graduation (diploma/TOR scan), and record internal audit justification notes. |
| **FR-31** | **Moderator** | **Job Posting Compliance Review:** The system shall allow the Moderator to review newly submitted job vacancies from employers, ensuring alignment with ethical employment standards, fair labor practices, and college policies before approving listings for public visibility. |
| **FR-32** | **Moderator** | **Community Feed and Discussion Moderation:** The system shall provide the Moderator with content moderation tools to monitor public posts, inspect reported discussions or inappropriate comments on the Community Feed, and remove policy-violating items with author warning notifications. |
| **FR-33** | **Moderator** | **Institutional Event Planning and Authoring:** The system shall enable the Moderator to create, schedule, and publish campus and alumni events (`events`), configure venue locations, establish maximum attendee seat capacities, specify guest accompaniment limits, and upload promotional cover graphics. |
| **FR-34** | **Moderator** | **Event Gate Management and QR Code Scanner:** The system shall provide the Moderator with a mobile-optimized QR code scanning interface utilizing the device camera to validate attendee reservation passes at venue entrances and log verified physical attendance in real time. |
| **FR-35** | **Moderator** | **Official Campus Announcements Management:** The system shall allow the Moderator to author and publish institutional advisories (`announcements`), assign urgency priority badges (normal, important, urgent), and filter distribution to target specific academic departments or graduation cohorts. |
| **FR-36** | **Moderator** | **Campus Gallery Archive Curation:** The system shall allow the Moderator to upload, categorize, and caption commemorative photographs in the institutional alumni gallery (`gallery`), organizing archives by year and event category. |
| **FR-37** | **Admin** | **Registrar Masterlist CSV Batch Import:** The system shall allow the Administrator to batch-import official graduate records from standard CSV files into the `registry_records` collection, automatically mapping student IDs, graduate names, degree programs, honors, and graduation batch years. |
| **FR-38** | **Admin** | **Administrative Account Provisioning:** The system shall allow the Administrator to create, configure, and issue login credentials for privileged internal accounts, Moderators, and fellow Administrator users. |
| **FR-39** | **Admin** | **Role-Based Access Control (RBAC) Governance:** The system shall allow the Administrator to modify user roles strictly between Moderator and Administrator tiers, keeping Alumni and Employer roles structurally fixed. The system shall permit the Administrator to revoke or delete Alumni, Employer, and Moderator accounts, while reserving the deletion of Administrator accounts exclusively for the Super Admin. |
| **FR-40** | **Admin** | **Account Suspension, Locking, and Reactivation:** The system shall allow the Administrator to search all registered user profiles and immediately suspend, lock, or reactivate accounts to enforce platform security and disciplinary policies. |
| **FR-41** | **Admin** | **System Health and Resource Monitoring:** The system shall provide the Administrator with a centralized monitoring dashboard displaying active user counts, error logs, and real-time Cloud Firestore database and storage utilization (`system_health`). |
| **FR-42** | **Admin** | **Security Audit Log Inspection and Export:** The system shall enable the Administrator to filter, inspect, and export chronological audit logs (`audit_logs`) detailing user actions, timestamps, actor roles, target collections, IP addresses, and security severity levels. |
| **FR-43** | **Admin** | **Alumni Tracer and Institutional Analytics:** The system shall generate visual analytical dashboards and tracer study reports for the Administrator, illustrating alumni employment percentages, industry sector distribution, geographical concentration, and event engagement metrics. |
| **FR-44** | **Admin** | **Database Configuration and Index Maintenance:** The system shall allow the Administrator to verify database composite indexes, review Firestore security rule integrity, and manage operational platform configurations. |
