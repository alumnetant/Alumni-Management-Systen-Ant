System Flow Diagrams & Institutional Reports

This document provides a comprehensive comparative architecture illustrating the operational workflow of the St. Cecilia's College - Cebu, Inc. alumni network before and after the introduction of the automated AlumNet platform. The deliverable is divided into four standardized sub-sections:

Section Structure:
• E.1 – Current / Manual Flow of the System: Process narrative, Unicode box-drawing workflows, and Mermaid flowcharts of the pre-automation system.
• E.2 – Sample Reports (Current System): Replicas of paper-based registrar ledgers, tracer surveys, and manual sign-in logs.
• E.3 – Proposed Flow of the System: Automated cloud architecture, algorithmic verification, contactless QR check-in, and ATS pipeline.
• E.4 – Sample Reports (Proposed System): Real-time digital analytics reports, attendance audit reconciliation, and security resolution logs.

E.1 – Current / Manual Flow of the System

Prior to automation, alumni coordination at St. Cecilia's College operated entirely through physical logbooks, manual campus visits, telephone inquiries, unindexed paper forms, and static spreadsheets. Record validation was siloed between the Registrar's Office and the Alumni Office, leading to severe latency and data loss.

E.3 – Proposed Flow of the System

The automated AlumNet platform unifies registration, digital verification, networking, event ticketing, and career tracking into a reactive cloud application built with React, TypeScript, and Google Firebase Cloud Firestore.

Subsystem 1: Algorithmic Verification & Dispute Handling

flowchart TD A1([Alumnus Opens AlumNet Registration]) --> A2[Enters Full Name, Student ID, Course, Batch, 11-Digit Phone, Password] A2 --> A3[System Queries Firestore registry_records Collection in Real-Time] A3 --> A4{Registry Record Match Check} A4 -- Perfect Match & ID Unclaimed --> A5[Account Provisioned with isVerified: true] A5 --> A6[Audit Log Written to audit_logs Collection] A6 --> A7([Instant Access: Full Directory, Messaging & Digital Alumni ID]) A4 -- ID Already Claimed by Another User --> A8[Flagged as ID COLLISION] A4 -- Student Record Not Found in Masterlist --> A9[Flagged as PENDING REGISTRAR REVIEW] A8 & A9 --> A10[Account Created in PENDING_VERIFICATION State with Restricted Dashboard] A10 --> A11[System Dispatches conflicts-updated Event & Admin Alert Notification] A11 --> A12[Moderator / Registrar Representative Reviews Case in Admin Triage Queue] A12 --> A13{Moderator Investigation & Resolution} A13 -- Approve Claim --> A14[Account Upgraded to isVerified: true & User Notified] A13 -- Reject Claim --> A15[Account Set to DISABLED / Fraud Prevention Alert Sent]
